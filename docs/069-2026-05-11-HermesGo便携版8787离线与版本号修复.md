# 069-2026-05-11-HermesGo便携版8787离线与版本号修复

| 字段 | 内容 |
|------|------|
| 编号 | 069 |
| 日期 | 2026-05-11 |
| 参考 | `HermesGo/Start-HermesGo.ps1`、`HermesGo/build_zip_v3.py`、`HermesGo/scripts/Compile-HermesGoBootstrap.ps1` |
| 目的 | 归纳并修复绿色便携包中 WebUI 8787 长期 offline、版本号停留在 0.10、缺少 HermesGo.exe 等问题，并给出验证与打包方式 |

## 1. 问题归纳

1. **8787 端口 / WebUI 显示 offline**  
   根因：`Start-HermesGo.ps1` 中 `Start-WebUIProcess` 误用 `Test-DashboardReady`（9119 Dashboard）判断「WebUI 是否已就绪」。Dashboard 起来后函数直接 return，**从未启动** `runtime\hermes-webui\run.py`，8787 无监听，浏览器与 WebUI 自带离线探测均失败。

2. **「应为 v13 / 最终版 13，界面却是 10」**  
   根因：`hermes_cli/__init__.py` 中 **`__version__` 为 `0.10.0`**，Dashboard/WebUI 展示的 Agent 版本即为此 semver；与发行说明中的「DeepSeek v13」产品线命名不一致，易被理解为「配置版本 13」或「包世代 13」。  
   同步：`home/config.yaml` 中 **`_config_version` 曾为 `5`**，与当前代码默认 **`18`** 不一致，状态接口会显示偏低/待迁移的配置代次。

3. **`HermesGo.exe` 缺失、无法「自动升级」**  
   根因：可执行文件由 `create_hermes_go/HermesGoBootstrap.cs` 经 `csc` 编译生成，仓库工作区若未执行编译步骤则只有 `HermesGo.bat`。Bootstrap 内含 GitHub 资源自检与更新逻辑；无 exe 时用户只能依赖脚本入口。

4. **ZIP 解压后路径不识别 `app\runtime`**  
   部分打包脚本将 `runtime/home/...` 置于 `HermesGo/app/` 下，而启动器原先只尝试「上一级目录」回退，未尝试 **`HermesGo/app`**，导致在错误根目录下找不到 `python.exe`（与 WebUI 未启动问题叠加后更难排查）。

## 2. 代码与配置修改摘要

| 项 | 说明 |
|----|------|
| `Start-HermesGo.ps1` | 新增 `Test-WebUIReady`（请求 `http://127.0.0.1:8787/health`）；`Start-WebUIProcess` 改为基于 WebUI 就绪判断；增加 `app\runtime\python311\python.exe` 存在时将 `$root` 设为 `...\HermesGo\app`。 |
| `hermes_cli/__init__.py`（根与 `runtime/hermes-agent` 内各一份） | `__version__` → **`0.13.0`**，`__release_date__` → **`2026.5.11`**，与 DeepSeek v13 发行线命名对齐。 |
| `home/config.yaml` | **`_config_version: 18`**，与当前 `DEFAULT_CONFIG` 一致，避免新解压包显示过低配置代次。 |
| `HermesGo/scripts/Compile-HermesGoBootstrap.ps1` | 使用系统 .NET Framework `csc.exe` 编译 Bootstrap；若存在 `create_hermes_go/assets/icons/HermesGo.ico` 则嵌入图标（可选）。 |
| `HermesGo/build_zip_v3.py` | 以 **`HermesGo` 目录自身为 SRC** 打包；`Start-HermesGo.ps1` 始终从仓库根读取；输出到仓库 **`dist/`**（避免遍历写入中的 zip）；排除 `create_hermes_go`、`exports`、`workspaces` 等平行树；ZIP 内保持 `HermesGo/` + `HermesGo/app/...` 布局。 |

## 3. 如何重新打包

在仓库根下已生成压缩包路径示例：

```text
py -3 HermesGo\build_zip_v3.py
```

产物：`dist\HermesGo-<时间戳>-DeepSeek-v13-WebUI-portable.zip`（体积含 `data/ollama` 等完整运行时，约数 GB 属正常）。

编译 **`HermesGo.exe`**（含自动更新引导）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "HermesGo\scripts\Compile-HermesGoBootstrap.ps1"
```

再执行上述 `build_zip_v3.py` 可将新生成的 `HermesGo.exe` 一并打入 zip。

## 4. 建议验证步骤（与本次执行一致）

1. 解压 zip 至例如 **`E:\hermes-test`**，应得到 **`E:\hermes-test\HermesGo\`**（内含 `HermesGo.exe`、`HermesGo.bat`、`app\runtime\...`）。
2. **无界面自检**（不弹浏览器与 Chat）：

   ```powershell
   $env:HERMESGO_HEADLESS = "1"
   powershell -NoProfile -ExecutionPolicy Bypass -File "E:\hermes-test\HermesGo\Start-HermesGo.ps1" -NoOpenBrowser -NoOpenChat
   ```

   日志中应出现 **`WebUI process started`** 与 **`WebUI probe succeeded`**。

3. **Dashboard**：`http://127.0.0.1:9119/api/status` 中 `version` 为 **`0.13.0`**，`config_version` / `latest_config_version` 为 **`18`**，`hermes_home` 指向包内 `...\app\home`。

4. **WebUI**：`http://127.0.0.1:8787/health` 返回 **200**；首页不应再因 8787 未监听而长期 offline。

5. **CLI**（仅当前目录，不依赖系统 Python）：

   ```powershell
   $env:HERMES_HOME = "E:\hermes-test\HermesGo\app\home"
   $env:PATH = "E:\hermes-test\HermesGo\app;E:\hermes-test\HermesGo\app\runtime\bin;" + $env:PATH
   & "E:\hermes-test\HermesGo\app\runtime\python311\python.exe" -m hermes_cli.main --version
   ```

## 5. 包体积：2.46GB vs ~700MB vs ~42MB（哪个算「干净」）

| 体积量级 | 典型内容 | 是否符合「绿色免安装 + CLI + Dashboard + WebUI」 |
|----------|----------|--------------------------------------------------|
| **~2.4GB+** | `build_zip_v3.py` 默认遍历整个 `HermesGo/` 根目录：重复的开发镜像（`agent/`、`gateway/`、`tests/`…与 `runtime/hermes-agent` 重复）+ **`data/ollama/models`**（约 1.6GB Gemma 等）+ **`runtime/ollama`**（约 1.5GB 内置 Ollama）+ **`installers/`**（数百 MB） | 功能最全，但 **含大量与云端无关的冗余**；此前还曾因目录名过滤误伤 `venv` 内同名文件夹（已在全量/精简脚本中收紧过滤规则）。 |
| **约 600MB–1.1GB** | **仅** `runtime/python311` + `runtime/hermes-agent`（含 `venv`）+ `runtime/hermes-webui` + `home` 等；**排除** Ollama 运行时、预置模型、`installers`、根目录重复源码 | **最符合「干净便携 + 三端在线」**：与桌面上 **~700MB** 档属于同一类产品形态（具体 MB 数随依赖版本与压缩率浮动）。 |
| **约 40MB 量级** | 若错误地在打包时全局跳过目录名 `sessions` / `codex` 等，会 **误删 `venv/Lib/site-packages` 下同名目录**，得到极小 zip，**运行时必缺依赖** | **不符合**交付要求，属于损坏包。 |

生成「干净全功能」包请使用：

```text
py -3 HermesGo\build_zip_slim.py
```

产物形如：`dist\HermesGo-<时间戳>-DeepSeek-v13-WebUI-slim.zip`（约 **1GB** 量级），根目录仅入口文件 + `HermesGo/app/...` 运行时，并附带 `HermesGo/PACKAGE-SLIM.md` 说明缺少 Ollama 与预置模型。

## 6. 残留说明

- **WebUI「设置」里 `agent_version`: not detected**：常见于无 `.git` 的便携树，属检测链回退文案，**不影响** 8787 服务与 Dashboard 在线状态。若需徽章显示 semver，可后续改为读取已安装包的 `__version__`。
- 绿色包仍会在 **`app\home`、`app\logs`、`app\webui-data`** 写入用户数据；不要将整包只读挂载。
- **`logs/agent-progress.md`** 仅作仓库内进度审计，**不**打入 `build_zip_v3` 产出的 zip（`dist` 在 `HermesGo` 外侧，且默认不从仓库根打包 `docs/`）。
